# V2.12.1 — Patient Attachment Security, Storage & PHI Hardening

## 1. Summary
This release hardens patient attachment uploads, storage paths, signed download URLs, lab parameter ownership checks, and PHI-safe route behavior. It establishes strong boundary safety policies for all clinician-facing patient attachments and extracted lab parameters, ensuring complete security isolation.

## 2. Security Improvements
- **Binary file signature checks**: Scans buffers for PE/MZ and ELF signatures to prevent executable binary uploads.
- **Script pattern rejection**: Rejects files containing `<script`, `<?php`, `<html`, and `<svg` snippets.
- **Filename traversal protection**: Sanitizes file names to block directory traversal sequences (such as `..`, `/`, `\`, and their URL-encoded variations).
- **Double-extension rejection**: Disallows uploads containing unsafe double extensions (e.g., `.php.pdf`).
- **Zero-byte file rejection**: Blocks empty uploads.
- **PHI-safe storage paths without patient names**: Standardizes path generation to `patient-attachments/{patientId}/{attachmentId}/{safeFileName}`.
- **Signed URL lifetime reduced to 5 minutes**: Expirations are capped at 300 seconds; URLs are generated in-memory and never logged or stored.
- **Archived/deleted attachment download restrictions**: Downloading archived/deleted files is blocked by default unless requested by a super-admin in explicit audit mode.
- **Cache-Control: no-store on attachment and lab parameter routes**: Dynamic API endpoints return headers disabling local, browser, and CDN caching.
- **Fail-closed practitioner authorization logic**: Any failure in the practitioner validation middleware defaults to a forbidden state.
- **Lab parameter ownership validation**: Verifies that updated parameter records match the request scope's patient and attachment context.
