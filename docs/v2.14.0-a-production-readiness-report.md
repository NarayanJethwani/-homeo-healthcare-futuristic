## 2. Hardened Production Gates

The following vulnerability gates were established, verified, and locked in:

### A. Server-Only Execution Safeguards
To prevent leaks of editorial logic into client bundles, a server-only guard was integrated into `cmsManager.ts`. During build-time, bundlers will block compilation if any of these methods are imported by React Client Components.
- **Verification**: Tests compile and execute natively in the CommonJS test context, while the Next.js production compiler blocks client bundling.

### B. Spoof-Proof Identity Binding
Identity parameters (`actor`, `publisher`, `reviewer`) are no longer trusted from the request payload. The Next.js API endpoints (`route.ts`) have been hardened to bind these values exclusively to the validated server session snapshot returned by `authorizeRequest`.
- **Harden Detail**: All POST actions overwrite the request body's actor identity with `auth.session.name` and use `auth.session.role` for RBAC checks.

### C. Bypass-Review Enforcement
Direct transitions from `draft` to `published` (bypassing normal review stages) are blocked unless the authenticated user possesses the `"knowledge.bypassReview"` capability (restricted exclusively to `"super-admin"`).
- **Audit Logging**: Any approved bypass creates a security audit event with action `publish_bypass` containing a SHA-256 fingerprint hash of the draft payload to ensure immutability.

### D. Zero-Content-Duplication Version Semantics
Lifecycle status changes (e.g. `approved` -> `published`) do not duplicate content version snapshots in `knowledge_article_versions`. They reuse the existing version ID linked by `currentDraftVersionId` and update records in-place. Approved and published pointers in the draft reference exact immutable versions.

### E. Atomic Persistence & Production Fail-Closed
All status transitions execute within Firestore Transactions (`db.runTransaction`). If any write fails, all changes are rolled back. 
- **Production Guard**: If `process.env.NODE_ENV === "production"`, any database write failure throws immediately, preventing fallbacks to local memory stores (fail-closed behavior).

### F. RAG Cache Invalidation
On every successful transition, the Redis/in-memory cache is invalidated via `cacheService.clear()` to ensure the RAG vector path serves fresh content immediately.

### B. Firestore Security Rules (`firestore.rules` additions)
Add the following blocks to the databases block:

```javascript
    // ─── CMS Editorial Governance Collections ──────────────────────────────
    match /knowledge_article_drafts/{draftId} {
      allow read: if request.auth != null && (
        getUserData().role == 'super-admin' || 
        getUserData().role == 'clinical-reviewer' || 
        getUserData().role == 'editor'
      );
      allow write: if request.auth != null && (
        getUserData().role == 'super-admin' || 
        getUserData().role == 'editor'
      );
    }

    match /knowledge_article_versions/{versionId} {
      allow read: if request.auth != null && (
        getUserData().role == 'super-admin' || 
        getUserData().role == 'clinical-reviewer' || 
        getUserData().role == 'editor'
      );
      allow create: if request.auth != null && (
        getUserData().role == 'super-admin' || 
        getUserData().role == 'editor'
      );
      allow update, delete: if false; // Immutable snapshots
    }

    match /knowledge_review_records/{recordId} {
      allow read: if request.auth != null && (
        getUserData().role == 'super-admin' || 
        getUserData().role == 'clinical-reviewer' || 
        getUserData().role == 'editor'
      );
      allow create: if request.auth != null && (
        getUserData().role == 'super-admin' || 
        getUserData().role == 'clinical-reviewer'
      );
      allow update, delete: if false; // Append-only review history
    }

    match /knowledge_audit_events/{eventId} {
      allow read: if request.auth != null && getUserData().role == 'super-admin';
      allow create: if request.auth != null;
      allow update, delete: if false; // Write-once audit logs
    }
```
